# SATs Maths Roadmap - Hybrid Illustration Production Method

**Status:** Founder-approved workflow for future illustration production. The V5 creative system remains frozen.

## Rule

Use the production method that protects mathematical accuracy. Do not require every final asset to be generated, styled in SVG, or manually edited in one single method.

- **Precision/manual:** finalise mathematically positional or proportional structures in Canva or another deterministic vector-editing workflow, then subject them to mathematical checking.
- **Hybrid:** use the V5 SVG or styled draft as a visual base, then manually correct the exact mathematical content before final approval.
- **Image-engine-friendly:** use generated or styled visual work only where no mathematical scale, quantity, position or notation can be distorted; still apply the V5 style and maths check.

## Strand 1 classification

| Topic | Classification | Reason |
|---|---|---|
| 1.1 Place value | Precision/manual | Column alignment, digit positions and values must remain exact. |
| 1.2 Rounding whole numbers | Precision/manual | Number-line scale, midpoint, marker and arrow endpoint must be exact. |
| 1.3 Roman numerals | Hybrid | The teaching-board styling can be drafted, but Roman notation and conversion require deterministic checking. |
| 1.4 Negative numbers; intervals across zero | Precision/manual | Number-line ticks, across-zero movement and arrow endpoint must be exact. |
| 1.5 Factors and multiples | Hybrid | The visual treatment can be drafted, but array quantities and factor relationships require checking. |
| 1.6 Prime numbers | Hybrid | Dot quantities and factor-pair claims require checking. |
| 1.7 Order of operations | Hybrid | The layout can be styled, but expressions, brackets and worked results require exact review. |

No Strand 1 topic is image-engine-friendly as a final asset without a separate deterministic mathematical check.

## Asset handling

For each future topic, preserve:

1. A working or draft source.
2. A final approved master.
3. A website-ready export.

Use separate `working`, `final-approved` and `website-ready` locations when the next production batch begins. Do not replace a previously approved master; preserve its versioned source and export.

## Website boundary

Codex maintains the V5 split-card system, stable topic IDs, asset references, public-content boundary and future teacher-resource compatibility. Only final approved and mathematically checked website-ready assets should be wired into the public roadmap. This workflow does not add scoring, learner tracking, CRM, authentication or teacher-resource URLs.
